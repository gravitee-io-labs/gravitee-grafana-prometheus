Gravitee API Management · Grafana dashboard pack

Monitor every API, consumer and gateway from one set of dashboards

Six linked Grafana dashboards, from the executive overview down to the headers and payloads of an individual call, with SLOs, error budgets and alert rules included. This guide covers what each dashboard answers, how to install the pack, and how to work with it day to day.

3. Where the data comes from

The dashboards combine four sources that Gravitee already produces. Nothing is added to the request path.

SourceWhat it holdsUsed for
API analytics
gravitee-v4-metrics-* (Elasticsearch / OpenSearch)		 One record per API call: API, application, plan, subscription, status, total / backend / gateway latency, backend connect time and time-to-first-byte, payload sizes, rejection reason and rejecting policy, client country and city, user agent, URI, transaction id Everything per API, per consumer and per call
Gateway metrics
Prometheus endpoint /_node/metrics/prometheus		 Real-time gateway-wide request rates and status codes, connections, backend HTTP client, JVM heap / GC / threads, CPU, file descriptors Fleet health, real-time throughput, SLO burn rates, alerts
Node monitoring
gravitee-monitor-* (Elasticsearch / OpenSearch)		 Per-node JVM, CPU and memory snapshots written by every gateway Fleet view even where Prometheus is not deployed
Call logs (optional)
gravitee-v4-log-* (Elasticsearch / OpenSearch)		 Headers and payloads of each logged call, as received from the client, sent to the backend, returned by the backend and returned to the client. Written only for APIs with logging enabled. The Call Logs dashboard and the Request id links in the Drill-down
No exporters to configure. API, application, plan, latency split, rejection reason, geo-IP and user agent are recorded for every call out of the box. The per-consumer and per-path views work as soon as the data sources are connected.

4. Set it up

Requirements

ComponentVersion / setting
Gravitee APIM4.x with v4 APIs (the dashboards read gravitee-v4-metrics-*)
Analytics reporterElasticsearch or OpenSearch (the default APIM reporter)
Grafana10.4 or later (validated on 12.2)
Prometheus2.40 or later (validated on 3.5)

Steps

  1. Enable the gateway metrics endpoint

    In gravitee.yml (or the equivalent Helm values / environment variables):

    services:
  metrics:
    enabled: true
    prometheus:
      enabled: true
  core:
    http:
      host: 0.0.0.0          # reachable by Prometheus (default: localhost only)
      port: 18082
      authentication:
        type: basic
        users:
          admin: <choose-a-password>

    With Docker or Kubernetes environment variables: gravitee_services_metrics_enabled=true, gravitee_services_metrics_prometheus_enabled=true, gravitee_services_core_http_host=0.0.0.0. Keep port 18082 on a private network: it is the gateway's internal API.

  2. Scrape the gateways with Prometheus and load the rules

    rule_files:
  - /etc/prometheus/rules/*.yml          # copy prometheus-rules/*.rules.yml here

scrape_configs:
  - job_name: gravitee                   # keep this name: rules and dashboards use it
    metrics_path: /_node/metrics/prometheus
    basic_auth: { username: admin, password: <password> }
    static_configs:
      - targets: ['gateway-1:18082', 'gateway-2:18082']

    On Kubernetes, use your usual service discovery and keep job="gravitee".

  3. Add the data sources in Grafana

    TypeIndex / URLTime field
    Elasticsearch: API analyticsgravitee-v4-metrics-*@timestamp
    Elasticsearch: node monitoringgravitee-monitor-*@timestamp
    Elasticsearch: call logs (optional)gravitee-v4-log-*@timestamp
    PrometheusYour Prometheus URL–

    Name them as you like: each dashboard has drop-downs to pick them. To provision them instead, adapt grafana-provisioning/datasources/*.yml.

  4. Import the dashboards

    In Grafana: Dashboards → New → Import → Upload dashboard JSON file, once for each file in dashboards/. Alternatively, mount the folder and use grafana-provisioning/dashboards/gravitee.yml. All six are tagged gravitee and linked to each other.

  5. Pick the data sources and check

    Open Gravitee · API Program Overview and select your data sources in the top bar. The API calls and Gateway nodes up tiles should show values within a minute. If they don't, see Troubleshooting.

  6. Optional: enable call logging on the APIs to inspect

    In the console: APIs → your API → Logs → Configure Reporting, turn logging on, and choose what to log (client side and/or backend side, request and/or response, headers and/or payload) and, ideally, a condition. Through the Management API, the API's analytics.logging block:

    "logging": {
  "mode":    { "entrypoint": true, "endpoint": true },
  "phase":   { "request": true, "response": true },
  "content": { "headers": true, "payload": true },
  "condition": "{#request.headers['X-Debug'] != null}" }

    The condition is evaluated when the request arrives, before plan selection, so it can select on the request (a header, a path, a method, a time window with #request.timestamp) but not on the response status or the application. The demo logs a fixed 1-in-5 sample with {#request.id.hashCode() % 5 == 0}. A logged call takes about 2 KB, against a few hundred bytes for its analytics record: log what you need, for as long as you need it.

Connect-time spikes point to network, DNS or TLS problems towards the backend. A rising TTFB with flat connect time means the backend itself is slow. Horizontal bands in the heatmap reveal two populations of calls, e.g. cache hits and misses.

8. Consumers, Plans & Tenants

The business view: who consumes the APIs, on which plans, with what experience. Useful for API product managers, partner managers and capacity planning.

  • Application scorecard: one line per application with calls, P95, number of APIs used, bytes served, 4xx, 5xx and rate-limited calls.
  • Plans & subscriptions: usage per API and plan, the number of applications on each plan, and the most active subscriptions.
  • Business dimensions: traffic and quality of service by tenant, channel and plan name, or any value you choose. These are recorded with the Assign Metrics policy (see Customise).
  • Where consumers are: map, operating systems and devices, user agents.

10. SLOs & Error Budgets

Turns monitoring into commitments. The default objective is 99.5% of calls without a server error over 30 days, an error budget of 0.5%.

  • Availability SLI (30d) and Error budget remaining: where the platform stands against the monthly objective.
  • Error budget burn rate: 1× means the budget will last exactly the month. 14.4× sustained for an hour consumes 2% of the monthly budget and pages someone; 6× over six hours raises a ticket.
  • Per-API SLO compliance: availability, share of the error budget used, P95 / P99 and slow calls for each API over the selected range. Above 100% budget used, that API breached its objective for the period.
  • Firing SLO alerts: alerts currently firing from the bundled rules.

11. Call Logs

The forensic view: what exactly went over the wire for a given call. It reads the call logs Gravitee writes for APIs with logging enabled (see Set it up, step 6). In the demo, 1 call in 5 is logged on every API.

SectionWhat it shows
Logged callsNumber of logged calls and the share of all calls they represent, logged failures, calls the Gateway answered itself (rejected before reaching the backend), and rejections by error key
Call log explorerThe latest logged failed calls and all logged calls, with client status and backend status side by side. not called means the Gateway rejected the call (plan security, rate limit).
Call detailOne call (the one whose request id you clicked, or the latest): a summary, the body at each of the four hops, and the headers at each hop
Hop by hop: 1. client → Gateway, 2. Gateway → backend, 3. backend → Gateway, 4. Gateway → client. Comparing 1 with 2, or 3 with 4, shows what the policies changed: a transformation, a removed or masked field, an added header. A 502 with a body at hop 3 is the backend's own error; a 401 with not called never reached the backend.
Sensitive data. Call logs can contain personal data and credentials. The dashboard hides API keys, Authorization and cookie headers, but they are stored in the index: give the call-logs data source to the people who need it only, and keep the index's retention short.

13. Customise

Add business dimensions Enterprise

The Assign Metrics policy records any value on the call's analytics record as custom.<name>. Add it to an API or plan flow:

{ "policy": "policy-assign-metrics",
  "configuration": { "scope": "REQUEST", "metrics": [
    { "name": "tenant",
      "value": "{#request.headers['X-Tenant-ID'] != null ? #request.headers['X-Tenant-ID'][0] : 'unknown'}" },
    { "name": "plan", "value": "Gold" } ] } }
  • Always give the expression a fallback: a null value drops the metric.
  • A literal value on each plan's flow ("plan": "Gold") gives readable plan names in every plan panel. Without it, plans appear by id.
  • New dimensions can be used straight away in the Filter bar (e.g. custom.tenant = acme-bank). To chart one, duplicate a tenant panel and change the field.

Change objectives and thresholds

  • SLO objective: replace 0.005 in gravitee-slo.rules.yml (e.g. 0.001 for 99.9%) and in the "Error budget used" calculation of the per-API SLO table.
  • Colour thresholds: edit a panel → Thresholds. Defaults: response time 300 ms / 1 s, gateway overhead 20 / 50 ms, heap 75 / 90%.
  • Alert thresholds: edit gravitee-alerts.rules.yml.

14. Troubleshooting

SymptomCheck
Analytics panels emptyThe analytics data source points to gravitee-v4-metrics-* with time field @timestamp; the APIs are v4 APIs; analytics are enabled on the API; the time range covers traffic.
Prometheus panels empty / "Gateway nodes up" is 0The metrics service is enabled; the internal API listens on 0.0.0.0; the scrape job is named gravitee; the basic-auth credentials match. Check the target in Prometheus → Status → Targets.
Throughput looks higher than expectedOnly series with local ending in :8082 are API traffic. If your gateway listens on another port, replace :8082 in the queries and the rules.
SLO panels emptyThe recording rules are loaded (Prometheus → Status → Rules). The 30-day SLI needs history, so it fills in progressively.
Tenant / plan-name / channel panels emptyThey need the Assign Metrics policy (see Customise).
World map without a backgroundThe basemap uses public Esri tiles; the browser needs internet access to services.arcgisonline.com.
Call Logs emptyLogging is enabled on the API and its condition matches some calls; the call-logs data source points to gravitee-v4-log-*. A request id opened from the Drill-down shows nothing when that call was not logged.
Call Logs search finds nothingPayloads are split on spaces only, so use wildcards: *EUR* rather than EUR. Headers are stored but not searchable.
v2 (legacy) APIs missingv2 APIs report to gravitee-request-* and gravitee-log-* with a different schema and are not covered by this pack.
